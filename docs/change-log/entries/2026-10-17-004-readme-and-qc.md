## B. What was changed?

**Previous behaviour.** `README.md` was a 263-line "planned project" overview covering objectives, target users and 8 planned steps, but no architecture diagram, no environment setup, no runnable commands, no dataset acquisition instructions, no test/run commands, no links to per-topic documents, and no statement of what had been verified as implemented.

**New behaviour.**

1. `README.md` is now a professional entry point with:

   - a titles + one-line summary plus an explicit "this is not an earthquake early-warning system" caveat;
   - a boxed **Project status: specification only — no implementation** banner that states that no `src/`, `tests/`, dependency file, dataset, trained model or result exists, names the authoritative status report, and warns that no performance number exists anywhere in the project;
   - the problem statement, key features (each marked `[PLANNED]`), scoped limitations, an architecture diagram, the technology stack, repository structure, environment setup, dataset setup, **but with the latter four each stating that no dataset/code/environment exists and that the commands are the *intended* form, not working commands**;
   - intended training, inference, evaluation, optional-demo and testing command shapes each fenced by `> [PLANNED]` lines;
   - a full **Documentation** link table (15 entries: PRD, audit, architecture, reasoning, tech-stack, system-flow, testing, experiment, dataset, roadmap, reproducibility, status, and change-log docs plus `DOCUMENTATION_QC_REPORT.md`);
   - preserved references to PhaseNet and STEAD with a warning that no citation has been verified;
   - no fabricated badge, number, screenshot or figure.

2. `DOCUMENTATION_QC_REPORT.md` (QC-001) — the Phase 10 documentation quality-control report, with:

   - the 540-local-links consistency check (before: 27 broken; after corrections: **0 broken**);
   - the 11-Mermaid-diagram audit (all present and well-formed by inspection; live rendering unchecked);
   - architecture ↔ explanation alignment, PRD ↔ architecture requirement-coverage proof (84 of 84 `FR-*` with acceptance criteria), roadmap coverage of every `Must` requirement, contradiction analysis (two intentional non-contradictions found), technology-status consistency table, implementation-status-evidence table, scientific-term audit, and a 7-item "no fabrication" checklist.

## C. Why was this change necessary?

1. The task's Phase 9 required that the README be a professional entry point linking every major document and matching the repository's actual commands — but marking unimplemented functionality as planned rather than as working. Without it, a fresh clone has no guidance on where to start.
2. The task's Phase 10 required a documentation quality-control pass reporting every discrepancy found.
3. `README.md`'s own earlier text warned that planned features should not be reported as completed features; that warning needed to be carried into the entry point's status banner and thus made impossible to miss.

**Evidence:** the task brief's Phase 9/Phase 10 deliverable list, the audit's finding that only single-topic documents and a short status paragraph existed, and the QC probe's discovery (before correction) of five malformed markdown links and one path error.

## D. Why was this approach chosen?

**Chosen approach:** rewrite the README at its canonical path, preserve v0.1 verbatim in `docs/archive/`, produce a per-check QC report rather than a single-pass "all clear", and fix the two link defects uncovered by the QC probe as part of this change.

**Alternatives considered:**

| Alternative | Assessment | Why not chosen |
|---|---|---|
| Edit v0.1's README minimally (add links) | Smallest diff | Would preserve the original's lack of an architecture diagram, lack of any instruction shape, and the "Planned Repository Structure" that is no longer the canonical structure. The structure is now `docs/TECHNICAL_ARCHITECTURE.md` §4, not the `src/preprocessing.py` monolith in the v0.1 README. |
| Delete v0.1's README | Clean history | Preserved alongside PRD and tech.md as `docs/archive/README-v0.1-original.md`, for the same traceability reason as the other two. |
| Carry only one documents index | Shorter | The QC report and the `README.md` index serve different audiences: one tells a new reader where to find the design, the other proves the design is consistent. Collapsing them would make both less useful. |
| Not report the five `](../PRD.md])` link defects | Cleaner change-log | The change-log rules require transparency. A defect that was corrected still belongs in the record; hiding it would misrepresent the quality of the subagent contribution. |
| State the new README's commands as working | More direct | Would contradict the audit, the status report, the change-log rules, and the task's explicit instruction to "mark the relevant instructions as planned instead of providing commands that do not work". |

**Trade-offs accepted:**

- The new README repeats material that is covered at length in `docs/`; that cost is inherent to an entry point and every repeated claim links to its canonical document rather than restating it.
- The README is longer than before, but the reproducer's time saved exceeds the extra scan time of a visitor who does not intend to reproduce.
