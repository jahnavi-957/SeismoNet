## C. Why was this change necessary?
Task 3 required Task 2's artifact verification to be parlayed into a real `splits/` that `SC-8` ("event-level split with zero leakage") can be checked against, with event counts / trace counts / P/S coverage per partition, a documented seed/ratios/provenance, and a passing zero-overlap guard — without substituting synthetic fixtures for real splits. ## D. Why was this approach chosen?
Selected: the **existing deterministic `source_id` splitter** (`split.py`) with seed 0 and roadmap `70/15/15` — not a new random split per run — because (a) the split must be reproducible on the same host (`FR-026`/`REPRODUCIBILITY.md` §6) and the seed+ratios+`source_id` hash are the whole provenance, (b) regenerating from sorted `source_id` values makes `splits/` reloadable without storing the CSV in history as a blob (the CSV is committed because it is small and `FR-005` requires it). Alternative considered: reuse the INSTANCE Counts sample's or ESSD's quoted 60.3/10/29.7 shipped split — rejected because the Counts **metadata shipped no `split` column at all** (verified in entry 011), so reuse is impossible; generating a new split is also the more general path for non-INSTANCE candidates. `0.70/0.15/0.15` was preferred to `0.60/0.30/0.10` because `DEVELOPMENT_ROADMAP.md` P1 already names 70/15/15 as the SeismoNet default when the upstream column is absent.
