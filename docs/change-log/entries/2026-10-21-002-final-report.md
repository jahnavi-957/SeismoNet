## C. Why was this change necessary

The master next-step prompt required a concise report structure suitable for a college mini-project with
the sections *Introduction → References*, filled only with verified facts. Until now the repository
contained the section **scaffold** (`docs/REPORT_SCAFFOLD.md`) and the supervisor-facing package, but no
finished written report to submit. The event-table discrepancy had to be corrected at the same time,
because the report quotes the same artifact and the two documents must not contradict each other.

## D. Why was this approach chosen

- The report is written from the run artifacts (`run.json`, `config_snapshot.yaml`, `event_breakdown.json`,
  `protocol.json`) and the source code, not from prose summaries, so every number is traceable to a file.
- The architecture section was derived by reading `src/seismonet/model.py` rather than from the
  design documents, because an earlier draft of the report described `kernel_size = 7` convolutions,
  which the implementation does not use; the draft was corrected **before** the report was saved.
- The report is a separate document rather than an expansion of the supervisor package: the supervisor
  package is a decision document (B1–B10), the report is a submission document (1–11), and they are
  read at different times by different people.
- Alternative considered: writing the report directly into `README.md` — rejected, the README is the
  repository entry point and is already at a workable length; the report is 11 sections long and would
  bury the quick-start material.
