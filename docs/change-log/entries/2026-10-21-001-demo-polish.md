## B. What was changed

- `scripts/demo_validation.py` gained a `--list` mode that prints every permitted validation trace with its index, event id and reference P/S arrival samples, then exits without loading a model. The argparse `epilog` now documents the four invocation styles (default, `--index`, `--trace`, `--list`).
- Three example demo figures were generated from the frozen checkpoint and frozen protocol, each showing a different regime so the viva can illustrate the model honestly:
  - `example_success_FDMO.png` — `11210661.IV.FDMO..HH`: P residual `0` samples (TP), S residual `−16` samples (TP).
  - `example_failure_MMO1_HN.png` — `11043661.IV.MMO1..HN`: P predicted `1621` samples away from the reference (out of tolerance FP), no S pick.
  - `example_missing_s_APPI.png` — `1114321.IV.APPI..EH`: missing-S trace, P predicted `+62` samples (out of tolerance).
- `tests/test_demo_validation.py` was added so the demo is covered by the normal suite instead of being an untested script.

## C. Why was this change necessary

The master next-step execution prompt required that any new functionality have focused tests ("Any new functionality must have focused tests") and that the demonstration be explainable during a viva. The demo existed but had no automated coverage of its most important property — that it can only reach validation data — and there was no discoverable way for a user to find a trace to show without reading the metadata CSV by hand. The `--list` option was started in a previous session and left untested and undocumented in the README.

## D. Why was this approach chosen

- A CLI listing is the smallest thing that makes the demo usable: it needs no new dependency, no server and no browser.
- The tests drive the script through `subprocess` exactly as a student would, so they cover argument parsing, the path guards and the figure rendering, not just helper functions.
- Three figures (success / failure / missing-S) were chosen over one because a single success case would misrepresent the system; the failure and missing-S cases are the honest limitations the report documents.
- Alternative considered: a Streamlit/Gradio app — rejected, the technical-stack note and the master prompt both forbid adding a web framework for presentation, and the model call is a single forward pass.

## E. How was it implemented

- `scripts/demo_validation.py`: `--list` branch placed after the validation-event/test-event overlap guard and before model construction, so listing never touches the network.
- `tests/test_demo_validation.py`:
  - `test_demo_list_prints_only_validation_traces` — asserts exactly `210` traces, every listed event inside the recorded validation event set and none inside `splits/test.csv`.
  - `test_demo_rejects_a_test_split_trace` — picks a real trace whose `source_id` is in the test split from the local sample metadata and asserts a non-zero exit with the message `not in the permitted validation subset`.
  - `test_demo_renders_figure_for_a_validation_trace` — renders `--index 0` into `tmp_path`, asserts the PNG exists, is larger than 5 kB, decodes to a >100×100 image, and that stdout carries the protocol id, the reference arrivals and the `Test split not loaded` notice.
  - `test_demo_cli_help_mentions_validation_only_usage` — asserts the help text advertises `--list/--index/--trace` and the validation-only scope.
  - Tests that need the local INSTANCE sample (`hdf5`/`metadata`) skip cleanly when the sample is absent, so the suite never depends on the temp data directory being present.

Verification commands:
